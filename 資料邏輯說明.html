資料來源與計算規則說明

提案資料是怎麼算出來的

工具讀入兩份 Excel，經一層共用的資料整備，產出一份提案 Word、一份四分頁 Excel 與一份提案附件 Excel。本頁逐表說明每個欄位的來源、篩選條件、排序規則與計算公式，供核對之用。核價公式與各項統計規則均依支付標準條文訂定，並與既有試算程式逐步對拍確認一致。

核價公式

支付標準第 40 條
第 40 條 · 小數處理（一律無條件捨去）
// 核算價小於 5 元 → 取至小數點後第 2 位
if (v < 5)   截斷至小數 2 位
// 5 元以上、未滿 50 元 → 取至小數點後第 1 位
if (v < 50)  截斷至小數 1 位
// 50 元以上 → 取至整數
else         截斷至整數
參考十國藥價法
調高後支付價 = 第40條進位( 十國中位價 × (1 + 加計比例) )
參考成本價法
小數誤差已做防護。電腦以二進位儲存小數，3.8 × 1.2 在機器裡其實是 4.559999999999999 而非 4.56。若直接無條件捨去會誤得 4.55，比正確值少一分錢。本工具在每次截斷前先還原到 15 位有效位數，把這類機器誤差清掉再截斷，因此 3.8 × 1.2 正確得到 4.56；真實資料本身就是 4.55999 的情形則不受影響，仍正確截為 4.55。同樣的防護也套用在加成級距的判定上，避免金額加總的累積誤差讓案件落入錯誤級距。
整體藥費與財務衝擊
整體藥費 = 調高後支付價 × 同分組近三年平均申報量
財務衝擊 = (調高後支付價 − 現行健保價) × 同分組近三年平均申報量

占率位數

占率依數值大小自動決定小數位：10% 以上取整數、1～10% 取 1 位、未滿 1% 則補到第一個有效數字為止（例 0.05%）。此規則與既有試算程式一致。

與既有試算程式的差異

本工具的計算結果已與既有試算程式逐步對拍。以下三處為刻意調整，會使少數案件的結果與過去不同，先行說明。

一 · 級距邊界依法條改為「小於等於」
既有程式的判定式，讓每月申報金額恰好等於 500,000 或 1,000,000 時落到下一個級距；但支付標準條文寫的是「小於等於新臺幣五十萬元／一百萬元」。本工具依條文改為「小於等於」。
二 · 級距判定所用的金額
既有程式在跨 ATC 的分組上，取該分組「第一筆 ATC 群組」的金額來判級距；本工具一律採整個分組代碼的金額總計。一個分組代碼只對應單一 ATC7 碼時兩者結果相同，僅在少數跨 ATC 分組會有差異。
三 · 小數誤差防護
既有程式直接對機器浮點值做無條件捨去，少數金額會因二進位表示誤差少算一分錢（例：成本 3.8 元加成 20%，正確為 4.56，既有程式得 4.55）。本工具在截斷前先清除機器誤差，取得數學上正確的結果。受影響的多為小數點後第二位的個位數差異。

驗證方式

  1. 核價公式逐步對拍。成本法的四個步驟各自的中間值，與既有試算程式逐一比對，14 組測試值除小數誤差防護造成的差異外全數相符。
  2. 十國藥價法手算驗證。218.75 × 1.2 = 262.5 → 262；成本法 130.55 × 1.5 = 195.825 → 195.82 × 1.0505 = 205.71 → 205（領證）、→ 195（未領證）。
  3. 0 元項目年度歸零。生效民國 111 年的項目，112～114 年金額與數量均歸零，逐筆檢核無誤。
  4. 表二新規則檢核。以含「0 元且不良品註記 Y」的測試主檔驗證：項目數計入、支付價欄不出現 0、表下備註行數與分組數相符；BOTH 模式確實產出兩張表且編號連續。
  5. 同 CODE 多列合併檢核。1 項藥品配 5 筆文號（僅第 1 列填值）：合併為 1 項，說明一列出 5 筆、表五 1 列、核價表 1 張；另測值填在第 2 列、文號重複、混填 ATC_MODE 等情形，取值與去重均正確。
  6. 檔案實際開啟驗證。產出的 Word 與 Excel 以實際文書軟體開啟並轉為 PDF，檢查版面、編號連續性與合併儲存格；需求檔範本確認下拉選單與「填表說明」分頁正常。
  7. 全流程自動化測試。上傳兩檔 → 預覽 → 產出 Word 與 Excel，確認無任何錯誤。
